# No toasts (2026-09-30)

Pete's rule: Vignette says what happened on the things already on screen, the way the copied mark
and the send mark do on a card. The toast code is removed, not hidden, so nothing can call it again.

## What each toast becomes

| Toast | When | Instead | Why |
|---|---|---|---|
| "Copied to clipboard", "Copied N images", "Copied path" | A copy with no card of it on screen, from a URL or the menu | The card comes up as the lone thumbnail with the copied mark, as a failed send's card does. For several, the first comes up and its mark counts them ("Copied 3") | The card is what was copied. `hold` in `ThumbnailController` already does this for a send |
| "Stitched N images, copied" | A stitch whose stack closed before it landed, or a `vignette://stitch` | The stitched card, as above | The stitched image is the thing made |
| "Could not copy the drawing; see the log" | Done's or Copy Drawing's rendering failed | The card takes a "Not copied" mark with a short reason (`Rendering.Failure.reason`), brought up if it is not on screen, held three times as long as the copied mark. A card in the editor, or on its way home, shows it when it lands | The same place a failed send reports. The copied mark it replaces is already taken back |
| "Could not render the drawing; see the log" | `copy-annotated` failed | As above | Same failure |
| "Couldn't update/install the Vignette plugin for X" | A launch update or setup's install failed | The log. The Agents tab says a failure of its own switch under the agent's name, as it already did; after a failed install from setup its switch reads off | A launch update is not something the person asked for. The Agents tab is where the plugin is shown |
| "Apple screenshot defaults restored", "No Apple defaults were recorded" | The Settings window's Restore… or the URL | The button reads Restored and greys out while the settings match Apple's recorded values (`Settings.appleRestored`); the URL answers in the log | The button is the thing pressed. It is already disabled when nothing was recorded |
| "settings.json did not parse…" | A launch that set the file aside | A warning at the top of the Settings window's General tab for that launch, and the log | Only a person who edits the file by hand meets this, and the Settings window is where they look |
| The editor's "Copied drawing", "Copied/Cut N marks" | ⌘C and ⌘X in the editor | Nothing | macOS apps say nothing on a copy. A cut shows itself: the marks leave |
| The editor's "Images can't be pasted here", "Only marks and text can be pasted here" | ⌘V with something the editor cannot take | The system beep | What macOS does for a key that cannot act, and what the strip already does for an action a card cannot take |
| The debug panel's toast preview | Tweaks | Removed | Nothing to preview |

## Also removed or renamed

- `FeedbackToast`, `model.feedback`, `showFeedback`, `present(toast:)`, `AnnotatorToast`, the
  editor's `.toast` effect and `onToast`, and `[state] stack.feedback`.
- `ui.toastSeconds` becomes `ui.markSeconds`: it is how long a card's mark stays. A settings file
  that set `toastSeconds` loses that value and gets the default.
- AGENTS.md says Vignette has no toasts and where feedback goes instead.
- `[state] stack.cards` reports each card's `copied` and `notCopied`, in place of `stack.feedback`,
  and the e2e stitch scenario checks the stitched card comes up with its copied mark.
