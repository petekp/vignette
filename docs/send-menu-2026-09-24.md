# Send's menu: recent sessions first (2026-09-24)

Send's menu listed every session it could find, grouped by project and sorted by name. Pete wanted
it to list the sessions you are actually working in, most recent first. This plan records what was
decided with him and how it was built. Built 2026-09-24 and checked on this Mac: the five rows were
the five sessions used last, and More sessions held the other 28.

Later the same day Send gained a target and a default, and the menu became the way to change it:
`docs/send-and-reply-2026-09-24.md`. The order and the rows' sources below still hold, except the
project, which now comes from herdr.

## Decided

- **Show the five most recent sessions.** The rest go under "More sessions". A cutoff by count
  needs no tuning, the menu is never empty after a break, and the session you just used is on top.
- **One list, newest first.** Each row is the session's title, with its project and its agent in
  grey. Recency is the order, so project headings would only break it up. The reply target (the
  session a card came from) still leads the menu on its own.
- **What a row says comes from Claude Code and Codex themselves:** its title, its project and when it
  was last used. herdr is used to deliver to a Claude Code session, because no other stable way
  exists to put a prompt into a session that's already running.
- **The menu lists only sessions Send can deliver to.** That's every Codex thread, and the Claude Code
  sessions sitting in a herdr pane. A Claude Code session in a plain terminal is left out rather than
  shown greyed, so every row works. herdr is asked only which session ids are in panes.

## Where each fact comes from

| Fact | Claude Code | Codex |
|---|---|---|
| Which sessions are listed | The ones herdr reports in a pane, since only those can receive. Each has a transcript, `~/.claude/projects/<project>/<session id>.jsonl`, which the rows below read. | `thread/list` from `codex app-server`, as today |
| When it was last used | The `timestamp` of the last user or assistant entry in the transcript | `recencyAt`, which the app drops today. `thread/list` sorts by it when asked (`sortKey: recency_at`), so the fifteen it returns are the fifteen used last. |
| Its title | The last `ai-title` entry's `aiTitle`. Claude Code keeps it current. | `name`, as today |
| Its project | The folder herdr says the pane runs in. The transcript's `cwd` follows the session's shell, so a session that ran `cd .scratch` read as ".scratch". | `cwd`, as today |
| How to deliver | herdr, as today: find the pane holding that session id, then submit | `codex queue --thread`, as today |

Checked on this Mac, 2026-09-24:

- **herdr's counter doesn't say when a session was used.** `state_change_seq` is one counter shared
  by every pane, raised when an agent changes state (herdr's source, `src/app/actions.rs`). It
  restarts with herdr, and it doesn't move while a session works without changing state.
- **Nor does the transcript's modification time.** Claude Code writes entries with no message in
  them, such as `away_summary` and `bridge-session`, to transcripts it isn't using. One last used on
  2026-09-19 had today's modification time, as did three others at the same second. The last user
  or assistant entry's `timestamp` is when the session was last used.
- **herdr's pane title is the same title, cut to 34 characters.** The transcript has it whole.
- **Codex's listing marks threads that aren't send targets.** Some are `ephemeral`, and some have a
  `parentThreadId` (a sub-agent's thread). Both are left out.

Reading a transcript means reading its tail. Transcripts run to tens of MB. In the sixty used last,
the last `ai-title` was never more than 34 KB from the end, so the last 256 KB is enough. A session
with no title in its tail takes herdr's pane title.

## Not decided

- **Channels.** Claude Code's own way to push into a running session is channels
  (code.claude.com/docs/en/channels). It's a research preview. A custom channel loads only with
  `--dangerously-load-development-channels`, and each session must be started with the flag. It's
  the route to adopt once a custom channel no longer needs that flag, and then herdr isn't needed.
