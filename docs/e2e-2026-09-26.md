# End-to-end test, 2026-09-26

A first-time user's path through Vignette, driven on this Mac on the current `main`, with every
finding fixed in the same round where it is in scope.

## How it runs

- **The demo copy only.** A Release build of `main` with its own bundle id
  (`com.petepetrash.vignette.demo`), URL scheme, log, settings file and watch folder, built by
  `.scratch/demo-sync.sh`. Its Send logs the line instead of submitting it. Pete's own build and
  settings are not touched.
- **A fresh settings file** for the first launch, from `.scratch/setup-test.sh`, which also points
  the demo's copy of Apple's screenshot settings at a scratch folder.
- **Input is posted** with `scripts/input.sh`. Before every click, the window under the point is
  checked; before every key, `[state]` must show the demo's window is key.
- **Pete's pasteboard** is saved before the first test that copies and put back at the end.

## What it covers

1. First launch and setup: the welcome page and the folder row, the shortcut page with the double
   tap and a key combination, the Accessibility request, the skill page, and closing setup.
2. A capture: the thumbnail, a click into the editor, a box with a note, an arrow, a text, Done,
   and the card's flight home.
3. The stack: the shortcut, hover and focus, keys, a multiple selection and the strip.
4. An agent's push with marks, and Send and Reply through the reply helper.
5. A recording's card.
6. Settings and the menu bar menu.
7. A relaunch: drawings and settings survive.

## Results

Every step in the list above works. The test found three bugs, all fixed. Two presses were lost
once each and did not happen again in later tries.

### Fixed

1. **Setup lost the front after the Accessibility alert.** Deny, or Open System Settings and then
   quitting it without granting, left setup behind the app that was in front before. Setup was
   waiting on a page the user could no longer see.
   - `Accessibility.request()` now brings the window that asked back to the front when the grant
     has not come.
   - Measured: on both paths, setup was back in front 0.2 to 0.4 s after the other app took the
     front.
2. **The flight home after Done started with a blank.** For about 70 ms, the editor's frame showed
   only the dimmed screen, then the card appeared and flew home. The editor's window was ordered
   out in the same turn the flight was added, and the window server removes a window at once.
   - Now the editor's frame is hidden in the commit that starts the flight moving. Its window is
     ordered out three display refreshes later (`AnnotationController`'s `Removal`).
   - The flight's first frame was also blurred, from a lone thumbnail: it showed the card's small
     picture until the sharp decode arrived. It now starts from the editor's own decode.
   - A first version ordered the window out after three refreshes. That left the editor visible
     behind the moving flight for one frame, so the frame is hidden in the flight's own commit
     instead.
   - Measured at 60 fps on the final build, from a lone thumbnail and from the stack, for Done and
     for Esc: no blank frame, no editor behind the flight, and no blurred first frame, in 5 takes.
3. **Copy labelled a JPEG or HEIC capture as PNG.** The first file's bytes went on the pasteboard
   as `public.png` whatever the format was, so an app that decodes that type as PNG got a JPEG.
   - The bytes now go on under their own type. The PNG and the TIFF are made only when a paste
     target asks for them.
   - Checked with a JPEG, a HEIC and a PNG capture: each type holds the right format.

### Not reproduced

- **A drag drew nothing, once.** It was the first press in the editor after a thumbnail opened it.
  Six later tries with the same steps, including the same waits and captures, drew on the first
  press.
- **A click on the message field left the keys with the editor, three times.** The typing became a
  note beside the box, and the line Send made had no message. All three came right after the menu
  bar menu was opened and cancelled through System Events. Nine tries after that took the keys
  every time, including with another app in front. The Accessibility menu session is the likely
  cause, but that is not proven.

### Checked

- **Setup.**
  - The welcome page: macOS's Desktop prompt shows Vignette's explanation, and Allow turns the row
    into a check.
  - Open at login is saved as soon as it is switched.
  - The Accessibility alert comes up alone, with no Settings pane in front of it.
  - Key Combination… records ⌃⌥V and registers it at once. The shortcut opens the stack and the
    page says "There they are. Now try holding ⌃⌥V." Holding it opens the newest image, passing
    over four recordings, and the page says "That's the whole trick."
  - The skill page shows both agents as Installed. Done saves the choices and gives the front back
    to the app from before.
- **A capture.** The thumbnail and its hover: the Draw hint, Copy and Delete. A click opens the
  editor. The image came from the hover's decode in 1 ms, and the window took presses 10 ms after it
  came up. A box, a note typed right after it, an arrow and a text all draw. Done puts the drawing
  on the pasteboard: the rendering took 150 ms.
- **The stack.**
  - The shortcut opens it with the keys, and the arrows move the focus.
  - Space selects. The strip shows Copy, Draw, Stitch and Delete with their keys.
  - Cmd+C copies both selected cards. Cmd+S stitches them into one column.
  - A click on a second card while the first is in the editor swaps them. Esc sends a card home.
- **An agent's push.** A card "From Claude" with three marks, the agent's text in SF Mono. The file
  carries the agent's name.
- **A recording.** Its card shows the first frame and a 0:02 badge. Copy puts on its file URL and
  path.
- **Send.** The line leads with the message. The demo copy logs the line instead of submitting it.
- **Settings.** General, Screenshots and Agents show the setup's choices. Screenshots follows the
  folder set in macOS's screenshot settings.
- **The menu bar menu.** Every item, with the shortcut and the hold on the first two.
- **A relaunch.** Drawings, the agent's name on a card and the shortcut all survive.
- **Unit tests.** All 410 pass.

### Not covered

- **The skill page on a Mac without the skill.** Installing writes to the real `~/.claude` and
  `~/.codex`.
- **A capture with ⌘⇧4.** It saves to your real folder, so the test wrote its captures with
  `screencapture` into a scratch folder the demo watched.
- **Reply.** It was checked live earlier today (`docs/reply-command-2026-09-26.md`).
- **A physical click.** All input was posted with CGEvent.

### Seen, not changed

- **A flight is slightly softer than the editor.** Its picture measures 3155 against the editor's
  3680 on an edge-sharpness measure, at both ends of a flight. It was the same before these changes.
- **Some strings name Vignette where others use the bundle's name.** Setup's "Lets Vignette notice
  the double tap" and "Vignette has access to your Desktop", and the menu's "Quit Vignette", read
  "Vignette" in the demo copy, whose windows say "Vignette Demo". Only a fork would show it.
- **The folder row asks again on a new settings file,** even when macOS already allowed the folder,
  because the watcher waits for setup before it reads the folder.
